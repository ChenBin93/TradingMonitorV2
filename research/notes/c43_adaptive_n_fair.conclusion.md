## H1–H3 逐条裁决

- **H1 部分支持 (2/4)**: 走前法 (前半选最优 N=60, 后半比) 下, 自适应 N 在
  两个 1h 配置胜出 (BTC +0.485 vs +0.053, ETH +1.382 vs +1.007, L7/L9), 两个
  4h 配置落败 (L6/L8)。频率敏感: 1h 上自适应有用, 4h 上没用。
- **H2 不支持 (1/4)**: 即使基准宽松为**零优化 N=20 日** (Donchian 4 周默认,
  无任何选择偏差), 自适应 N 仍只在 BTC 1h 胜出 (L14); 4h 与 ETH 1h 全部落败
  (L13/L15/L16)。c41 H4 的 0/4 不是基准太严, 而是自适应 N 本身不稳健。
- **H3 不支持 (1/4)**: GBM null 净差修正后 (海龟汤: 固定 N null −0.283 负,
  自适应 null +0.046 近零, L2), 自适应超额只在 BTC 1h ≥ N20 (L21)。注意:
  自适应 null 比 N20 null 少亏 (波动缩放减少了随机游走上的 whipsaw) — 净差
  修正已扣除该属性, H3 的 1/4 是修正后的结论。

## 对用户反观点的回应 + "自适应 N 是否真的有用"

**用户对 c41 H4 的批评成立**: 事后最优固定 N 违反不可知性 (最优 N 漂移,
c41 H2 已证), 书 CH21"测试不用于发现"反对这种比法。c43 修正后:

**自适应 N 依然不稳健有用**: 在三个公平基准下 (走前法 2/4、零优化 N=20
1/4、null 净差 1/4), 自适应 N 只在 **BTC 1h** 配置稳定胜出, 其余 3 配置全部
落败。自适应的波动缩放逻辑 (低波动放大 N、高波动缩小 N) 在 1h BTC 上减少
whipsaw, 但在 4h/ETH 上反而劣于简单固定 N。**结论: 自适应 N 不是一个稳健的
改进, c41 H4 的负结果方向正确, 只是基准违规需要修正。**
