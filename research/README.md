# TradingMonitor — 量化研究

> 目标：在已验证的监控系统（docs/LIVE_SYSTEM.md）基础上，进行量化交易研究。
> 研究的目的是：① 继续提升指标监控系统；② 评估并逐步拓展为自动交易系统。

## 目录结构

```
research/
├── README.md          # 本文件：研究方向与进度
├── notes/             # 研究笔记（每项研究的背景/设计/结论）
└── scripts/           # 研究脚本（回测/实验，遵循性能规范）
```

## 研究纪律（重要）

1. **研究成果不直接进 live**：统一记录到 research/notes/，完整研究并确认后，
   再统一选择更新 live（避免半成品规则污染监控系统）
2. live 更新必须逐条对应研究结论（标注验证数据/条件）

## 性能规范（重要）

1. **数据加载**：一律 `load_all(timeframes=['1h','4h'])` 过滤加载（全量含 5M = 276s，过滤后 27s）
2. **长时间调参**：用"预计算 + 索引采样"模式（backtest_window_tune.py 的范式），
   避免每个采样点重复计算；窗口扫描只换索引区间
3. **单次分析**：向量化（numpy/pandas ewm/rolling），禁用逐根 Python 循环
4. **输出一律落盘**：脚本运行 `> research/notes/xxx.out 2>&1` 重定向到文件，
   需要查看时直接读文件/grep — 禁止为看截断结果重跑脚本
5. 所有结论标注 (目标, 窗口, 数据范围) — 见 30 章教训

## 研究待办（按优先级）

### P0 — 支撑现有系统的验证
- [ ] **波动率长记忆检验**：1H/4H 波动率序列 ACF（100-500 根滞后自相关是否显著）
      → 决定市场状态是否需引入波动率状态维度（ewm 收敛≠信息无关的实证）
- [ ] **实盘 vs 标记对照**：用户实盘交易记录 vs 系统场景标记的胜率对比
      → 量化人工溢价，校准系统胜率预期

### P1 — 监控系统提升
- [ ] **形态识别研究**：双顶/三推/熊旗的实时检测算法（当前误报率 52% 不可用）
      → 目标：误报 <10% 且保留 +4~7pp 增量（顺大环境）
- [ ] **多周期状态融合**：日线×4H×1H 状态组合 → 完整的状态矩阵（当前只用了 4H 场景）
- [ ] **信号触发后的演进追踪**：信号 K 之后的展开是否符合预期（4-8h 关键窗口）

### P2 — 自动交易系统评估
- [ ] **策略全集回测**：插曲系统 + BB 反转 + 力量过滤 的资金曲线（含滑点/手续费）
- [ ] **执行成本建模**：滑点、手续费、资金费率对 0.5ATR 小目标的侵蚀
- [ ] **风险数学**：凯利分数、最大回撤预算、多标的组合风险
- [ ] **模拟盘验证**：规则化执行 vs 人工执行的差距量化

## 已有结论速查（研究基础）

- 插曲(顺日逆时)是唯一稳定 edge：TP2.0 时多 57.8% / 空 60.8%（3年）
- BB 反转（日线空/中性 + 1H BB上轨破轨做空）：3年 68% 稳定（TP0.3-0.5 小目标）
- 多空力量（近30根）在插曲环境 + 同向极端：62.1%（+5.0pp）
- 入场价位优势：每好 0.15 ATR ≈ +14pp 胜率
- 订单管理（机械规则）是负优化——管理是人工 alpha
- 5M 反转 K 执行仅 4 大币有效（+2.4pp）
- 双命中真实赢面 42%：1H 粒度回测略高估
- 判定窗口 30 根 + 指标历史 120 根（切换灵敏度最优）
